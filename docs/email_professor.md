## 메일

**받는 사람**: 권재환 교수님
**제목**: [데이터베이스응용 01분반] 텀프로젝트 데이터 수집 방법 문의 (이성수)

```
교수님 안녕하세요, 데이터베이스응용 01분반 이성수입니다.

저희 조는 텀프로젝트 주제로 "KBO 야구 경기 기록 및 선수 통계 관리 시스템"을 진행하고 있습니다.
실제 경기 데이터를 사용하기 위해 아래 방법을 고려하고 있는데, 사용해도 괜찮은지 여쭙고 싶습니다.

1. KBO 공식 홈페이지(koreabaseball.com)의 경기 기록·선수 기록 페이지를 크롤링하여 수집
2. 이미 공개된 오픈소스 수집 도구(GitHub kbo-data, MIT 라이선스)를 활용
3. 네이버 스포츠 문자중계 데이터 수집 (투구별 구종·구속)

수집할 때는 요청 사이에 1~2초 간격을 두어 서버에 부담을 주지 않도록 하고,
수집한 데이터는 수업 프로젝트 용도로만 사용하며 보고서에 출처를 명시하겠습니다.
혹시 위 방법 중 사용하면 안 되는 것이 있거나, 직접 입력한 데이터만 써야 한다면 알려주시면 그에 맞추겠습니다.

감사합니다.
이성수 드림
```

## 바꾼 점 (작업지시서 초안 대비)

- "요청 사이 1~2초 간격" 한 문장을 추가했다. 크롤링 방식을 구체적으로 밝혀 두면 허용 판단에 도움이 되고,
  실제로 모든 크롤러(`crawl/`)가 그렇게 동작한다.
- 나머지는 초안 그대로. kbo-data 라이선스는 레포 `LICENSE`에서 MIT 확인(2026-11-05에도 동일).

## 답장에 따라 바뀌는 계획

| 답장 | 계획 |
|---|---|
| 모두 허용 | 그대로 진행 |
| 1번(KBO 크롤링) 불가 | kbodata 박스스코어만 사용 → 선수ID는 직접 만든 번호(이름+팀+시즌 기준)로, 선수 프로필은 소수 선수 직접 입력 |
| 3번(네이버) 불가 | 투구 테이블 제외, 시각화는 kbodata 타구 방향 스프레이 차트·기록 차트로 대체 |
| 직접 입력만 허용 | 가상 데이터 생성기(`tests/fixtures/make_synthetic.py`, `tools/perf_check.sql`)를 확장해 시연 데이터로 사용 |
