## 실제 검증 결과

- 10팀 × 타자/투수 × Basic1/2 = **40개 수집 단위 완료**. 각 팀의 Basic1·2 선수 ID 집합이 일치했다.
- CSV별 기본키 중복·빈 키 없음. 프로필 대상 playerId 누락 없음.
- 타율·출루율·장타율·OPS가 비어 있는 타자 **99행은 모두 0타수**다. 값을 0으로 추정해 채우지 않았다.
- 순위표의 승+패+무 = 경기 수를 10개 팀 모두 확인했다.
- PostgreSQL 16.2의 새 검증 DB에서 **KBO 전용 적재를 두 번 실행해도 건수가 유지**됐다.
  선수 585, 시즌 소속 585, 타자 기록 398, 투수 기록 281, 순위 10행.
- 경기 CSV 없이 적재했고, 경기 테이블은 0행이다. 박스스코어를 수집·검증 완료했다는 의미가 아니다.
- 새 스키마는 **테이블 21개·FK 29개·일반 뷰 16개·집계 MV 3개**이며 네이버 객체가 없다.
- 자동 테스트 **48개 통과**. 별도로 이전 24개 테이블 설계에서 두 번 전환해 선수·경기·기존 투구 보존과 새 적재를 확인했다.

## 프로필을 해석할 때 구분할 것

- 프로필은 **수집 시점 페이지의 표시 값**이다. 2025 시즌 프로필을 복원한 것이 아니다.
- 프로필에 상무가 표시된 선수 **29명**은 소속 원문을 그대로 보존했다.
  고양 히어로즈·울산 웨일즈 같은 표시 소속도 KBO 10개 구단 코드로 임의 변환하지 않고 원문을 보존했다.
  과거 시즌 팀과 현재 프로필 소속은 각각 `player_season`과 `player.current_team_name`으로 구분한다.
- 현재 등번호는 `player.current_uniform_no`에 저장했다. 과거 시즌 등번호에 복사하지 않았다.
- KBO 원본의 `0cm/0kg`는 미등록 신체 정보로 보고 빈 값/DB NULL로 변환했다.
  최종 프로필의 신장 누락 1명, 체중 누락 1명.
- 연봉은 별도 `player_salary`에 576행 적재했다. 이번 기준 연도는 **2026**로,
  크롤러의 기본 규칙(3월 이후 조회 연도)을 적용한 값이다. 2025 과거 연봉 자료로 쓰지 않는다.
  페이지에 연도가 명시되지 않은 경우 공식 계약 연도 확인이 별도로 필요하다.

- KBO 수비·주루 전용 시즌 표 및 엔트리 등록·말소 이력 수집.
- kbodata 전체 시즌 박스스코어 적재와 공식 시즌 기록의 실데이터 대조.
- 2025-06-01 테스트 원본의 타자 124행·투수 53행 이름→playerId 매핑 검증.
  playerId를 확보한 것과 이름만 있는 원본의 매핑 검증은 구분한다.

현재 화면은 공식 시즌 표와 순위를 직접 조회한다. 경기 결과·상대전적·타구 방향·경기 집계 백분위는 박스스코어 확보 후 사용한다.
