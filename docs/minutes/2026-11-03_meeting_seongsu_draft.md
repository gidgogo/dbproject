## 결정 사항

1. 주제: 스포츠 경기 기록 및 선수 통계 관리 — **KBO 야구**
2. 구현 범위: 경기 결과, 선수 프로필(개인정보 + 시즌 기록 + 선수 비교), 팀별 프로필, 순위, Savant식 시각화
   (참고: baseball-reference 선수 페이지, Baseball Savant visuals)
3. 기술 스택: PostgreSQL + Spring
4. 기본 데이터: kbodata(GitHub dev-bearabbit/kbo-data)로 KBO 게임센터 박스스코어 수집
5. 역할
   - 김경주: GitHub 레포, Spring 초기 설정, ERD(공동), 도메인별 API
   - 배인표: kbodata 결과 전처리
   - **이성수: ERD 설계, 추가 데이터 크롤링(선수 상세·playerId, 기록실, 네이버 문자중계)**
6. 일정: 11/9 ERD 초안·전처리·초기 세팅 공유 → 11/10 ERD 리뷰 회의 → 11/25 개발 완료 → 12/1 또는 12/3 발표(먼저 발표)

## 이성수 역할 관련 메모

- kbodata에는 선수 ID가 없어 이름으로만 구분됨 → KBO playerId를 크롤링해 선수 주식별자로 쓰기로 제안
- kbodata 타자 기록의 이닝별 컬럼(i_1~i_18)은 반복 그룹 → 타석 테이블로 정규화 (보고서 정규화 사례)
- 시즌 누적 성적·순위는 뷰로 계산하고, 기록실 값은 검증용으로 수집
